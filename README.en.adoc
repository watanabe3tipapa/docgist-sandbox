= DocGist

**Documents earn their value by being shared, not hidden.**

DocGist is a content site for sharing your AsciiDoc (.adoc) documents in a form that is easy to read — for both AI agents and humans. Centered on the affinity between AsciiDoc and AI, it offers a landing page, a tutorial, and a live playground that let you experience why explicit structure matters.

== Overview

DocGist is an Astro 7 static site that ships two tracks from a single repository: 1) human-readable HTML and 2) a set of .adoc templates to grow along with AI. Documents are treated not as artifacts to publish but as seeds to cultivate with AI — through real-time conversion, a syntax reference, and practical templates — so you can feel how AsciiDoc stays stable as the container for AI output.

== Concept (why "DocGist")

A gist embodies an open-sharing mindset: short fragments shared generously. DocGist extends that spirit to full documents, giving you a toolbox to take your .adoc seeds and grow them into a form readable by both AI and people, then publish them via GitHub Pages.

DocGist covers:

* A bilingual (ja/en) landing page and tutorial introducing AsciiDoc grammar
* In-browser real-time conversion with a Monaco editor + Asciidoctor.js
* An inline live demo on the LP plus a floating ".adoc syntax cheat sheet" island
* Ready-made .adoc templates: document / spec (PRD) / meeting notes / release notes
* A guide on how .adoc handles invisible characters (conversion preserves, not quarantines)
* Automatic build & deploy via GitHub Actions

== Main features

* AsciiDoc (.adoc) as the source of truth for the site content
* Node-only workflow: `npm run dev` / `npm run build`
* Edit .adoc in a Monaco editor → Asciidoctor.js renders HTML in real time
* "Structure at a glance" live demo on the LP that converts as you type
* A collapsible floating syntax cheat sheet (island-style UI)
* Four practical .adoc templates (document / spec / meeting / release notes) + English versions
* Neo-brutalism design (plain CSS / CSS variables, no framework)
* ja/en switching via Astro i18n routing

Content notes:

- Conversion is faithful, not quarantine: rendered previews do not sanitize invisible characters
- Templates are ready to use — just replace the `{{ placeholders }}`

== Getting started (facts only)

1. Install dependencies:

[source,shell]
npm install

2. Start the local dev server:

[source,shell]
npm run dev

3. Build and preview:

[source,shell]
npm run build
npm run preview

Sample output:

- `dist/` — the built static site (HTML/JS/CSS, including `templates/*.adoc`)
- `dist/templates/` — distributable .adoc templates

== Pages

* `/` — LP (Japanese)
* `/en` — LP (English)
* `/what-is-asciidoc` — AsciiDoc explanation (admonitions, tables, include, and more)
* `/playground` — live conversion playground (left: editor / right: output)
* `/templates/*.adoc` — downloadable templates (served statically)

== Documentation & learning path

Reading these in order helps you grasp the whole picture:

1. "What is .adoc?" — the basics of an explicitly-structured lightweight markup
2. "Structure at a glance" — experience real-time conversion in the live demo
3. "What is AsciiDoc" page — detailed grammar
4. "Grab a template" — download practical .adoc templates and try them in the Playground
5. "Invisible characters & .adoc" — security awareness and the normalization principle

== Repository layout (main files & directories)

- `astro.config.mjs` — site configuration (`base: /docgist-sandbox`, i18n)
- `src/pages/` — LP / explanation / playground (ja and en)
- `src/components/` — Playground, AsciiDocLiveDemo (live demo + cheat sheet)
- `src/scripts/playground.ts` — Monaco + Asciidoctor conversion with localStorage persistence
- `src/lib/` — `asciidoc.ts` (conversion), `link.ts` (base-path resolution)
- `public/templates/` — distributable .adoc templates (ja / en)
- `.github/workflows/pages.yml` — GitHub Pages deployment
- `README.adoc` / `README.en.adoc` — this bilingual README
